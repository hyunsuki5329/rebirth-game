# M11 — Save and Load

## Implementation
Profile persistence uses a schemaVersion 1 envelope with Bank Gold, clear count, settlement ID, Rebirth Count/Points/multiplier, stable upgrade/unlock IDs and master-volume settings. Runtime scene references and RunState are excluded. SaveCodec validates IDs, duplicates, nonnegative counts and finite/ranged values. Unsupported versions use the same preservation/recovery path as malformed data; there is no hypothetical migration framework.

GameBootstrap uses Application.persistentDataPath unless an explicit QA directory is configured. It loads before displaying MainMenu and saves after initialization, settlement, Rebirth, upgrade purchase and volume change. Failed saves retain the current in-memory Profile and previous valid file; Retry Save is explicit. The UI warns before quitting when persistence failed and states that active runs do not resume. Settings currently offer master volume in MainMenu/Hub; pause integration is M12.

ProfileFileStore writes and flushes profile.json.tmp, then uses File.Replace with profile.json.bak when a primary exists, or File.Move for a first save. Malformed/unsupported originals are moved to a unique .corrupt-* filename before fallback. Valid backup is preferred to a new Profile. Inability to preserve/read a primary blocks writes rather than overwriting it. Expected file failures are returned to the UI, not ignored or repeatedly logged as exceptions.
