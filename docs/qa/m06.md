# M6 — Weapons, evolution and pixel art

## Implemented scope
- Dagger, Sword and Greatsword retain distinct timing, range, movement and knockback. The user explicitly authorized Bow as a fourth weapon; PLAN.md records that scope change.
- Bow uses mouse aim and one arrow per accepted left click. Damage, timing, speed and lifetime are data-driven. UI weapon clicks do not also attack.
- Three capped run items, seeded reward choices and fresh-run reset are connected. Runtime stacks and evolution progress are separate from configuration assets.
- Three qualifying Dagger combos in one run unlock a piercing finishing wave. Wave hit/kill events participate in Momentum and reward calculation.
- Explorer, all four held weapons, Slime (Chaser), Goblin (Ranged) and Boar (Charger) use generated pixel artwork. Explicit Texture2D import, Point filtering, transparent sprites and white hit feedback are configured.
- The direct-play Unity menu and instructions are in ../PLAYTEST.md. Input Contract is unchanged.

## Verification coverage
- Core weapon statistics, item arithmetic, seeded choices and evolution thresholds.
- Real combat combos across rooms evolve Dagger within one run; restart clears evolution and items without mutating assets.
- Bow mouse-button selection and actual attack input, enemy hit, Momentum, wall collision, lifetime and effect cleanup.
- Piercing wave hits each target once, reports kills/rewards, stops at walls and expires. Its dedicated sprite cannot accidentally reuse the character image.
- Artwork references/import settings, shader compilation, all held weapon bounds and hit-flash activation/recovery.
- Independent review findings were fixed and re-reviewed: wave combat-event integration and accidental player-sprite reuse. Bow's incorrect automatic Cubemap import was corrected to explicit Texture2D and covered by asset tests.
