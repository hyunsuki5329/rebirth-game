# M9 — Main Menu, Hub and run result

## Implementation
MainMenu creates an explicitly owned persistent GameBootstrap session; no static global Instance is used. Hub and Dungeon are separate scenes. Scene transitions reject repeated requests while loading. Hub weapon selection applies to a newly created player; Dungeon's auto-start is disabled in the production scene so the session controls initialization.

RunFlow keeps ProfileData separate from RunState. Victory retains 100% of earned Gold and Death retains floor(50%) using configured rates. Only the active Run ID can settle and only while in Dungeon phase. Result UI shows earned Gold, retention and Bank Gold; returning to Hub preserves Profile while unloading actors/effects. The next run gets fresh HP, inventory, Momentum and weapon evolution.

GameFlowView presents menu/Hub/result controls and a Dungeon HUD with reward choices, Momentum, Combo/evolution and Boss HP. The development DungeonArena remains available independently. Roguelite > Play Vertical Slice now opens MainMenu.

## Validation scope
Core tests cover both retention rates, odd-number flooring, duplicate results and stale previous-run events. Scene integration follows victory through Hub, starts a fresh second run, and follows death back to Hub while checking profile retention and run-state reset. A virtual mouse test exercises actual menu, weapon selection, reward and return buttons.
